# SEO Audit - 2026-03-18

## Scope
- Repo audited: `C:\Users\Rodrigo\Documents\IAacademy\IANEXUS\05-web`
- Branch audited: `mvpv2`
- Audit type: technical + editorial SEO review
- Change policy: read-only; no application code changed

## Executive Summary
IA NEXUS is not yet well-optimized for organic discovery. The primary issue is not one isolated technical error; it is a combination of weak page-level metadata, thin editorial depth in several sections, limited search-specific information architecture, and inconsistent taxonomy during the transition from `areas` to `carreras`.

The most critical technical SEO problem is that key public pages currently inherit the same generic global `<title>` and `<meta name="description">` from the root layout instead of defining route-specific metadata. This makes `/`, `/blog`, `/areas`, `/estudiantes`, and `/dia-a-dia` look effectively identical to search engines at the metadata level.

The most critical editorial SEO problem is that several sections still read as curated product surfaces rather than mature editorial hubs. That weakens topical authority, internal linking depth, and long-tail discoverability.

## Top Priorities
1. Add route-specific metadata for all key public pages and dynamic detail pages.
2. Decide on one canonical taxonomy model (`carreras`) and align URL/filter language with it.
3. Expand editorial hub quality for `/blog`, `/areas`, `/estudiantes`, and `/dia-a-dia`.
4. Add machine-readable SEO primitives: `robots`, `sitemap`, canonical handling, and structured data.
5. Remove thin/placeholder or low-value content signals before pushing more traffic.

## Technical Findings

### 1. Generic metadata is being reused across core public pages
Severity: High

Observed behavior from the running app on localhost:
- `/` title: `IA NEXUS — Comunidad IA para estudiantes`
- `/blog` title: `IA NEXUS — Comunidad IA para estudiantes`
- `/areas` title: `IA NEXUS — Comunidad IA para estudiantes`
- `/estudiantes` title: `IA NEXUS — Comunidad IA para estudiantes`
- `/dia-a-dia` title: `IA NEXUS — Comunidad IA para estudiantes`
- `/login` title: `Login - IA NEXUS`

The same issue exists for descriptions on the major public routes.

Primary source:
- `src/app/layout.tsx`

Impact:
- weak SERP differentiation
- duplicated title/description patterns
- lower relevance matching for route-specific intents like tools, careers, blog, and student discounts

### 2. Route-level metadata coverage is incomplete
Severity: High

There is metadata for:
- `src/app/layout.tsx`
- `src/app/login/page.tsx`
- admin pages

But no page-level metadata was found for the main public discovery routes:
- `src/app/page.tsx`
- `src/app/blog/page.tsx`
- `src/app/areas/page.tsx`
- `src/app/estudiantes/page.tsx`
- `src/app/dia-a-dia/page.tsx`
- `src/app/dia-a-dia/fundamentals/page.tsx`

Dynamic content pages also lack `generateMetadata`:
- `src/app/blog/[slug]/page.tsx`
- `src/app/herramientas/[slug]/page.tsx`

Impact:
- detail pages cannot emit content-specific titles/descriptions/Open Graph
- blog posts and tool detail pages miss strong search snippets

### 3. No visible sitemap or robots implementation
Severity: High

No `robots.ts`, `sitemap.ts`, `public/robots.txt`, or `public/sitemap.xml` was found.

Impact:
- weak crawl guidance
- no explicit discovery map for Google/Bing
- missed opportunity to prioritize editorial and detail pages

### 4. No visible structured data / schema markup
Severity: Medium-High

No Article, BlogPosting, WebSite, BreadcrumbList, CollectionPage, or SoftwareApplication schema implementation was identified in the app router.

High-value targets missing schema support:
- home as `WebSite` / organization-level page
- blog index as `CollectionPage`
- blog posts as `Article` or `BlogPosting`
- tool detail pages as `SoftwareApplication` or a custom editorialized product schema pattern
- breadcrumbs on tool/post detail pages as `BreadcrumbList`

Impact:
- weaker rich result eligibility
- weaker machine understanding of content relationships

### 5. Canonical handling is absent or not explicit
Severity: Medium

No route-level canonical configuration was found in metadata.

This matters more because:
- `/areas` is filter-driven
- there is ongoing naming drift between `areas` and `carreras`
- query-param pages can fragment index signals if left unmanaged

Impact:
- possible duplicate URL variants over time
- weaker authority consolidation on category/career pages

Severity: Medium

`/blog` is structurally better than the rest, but it still needs stronger editorial trust signals:
- more published posts
- clearer thematic clusters
- stronger archive depth
- author/date/category conventions

### 10. Placeholder / low-volume content still hurts credibility
Severity: Medium-High

There is still very little real editorial inventory in the database from an SEO perspective.

Observed from the database:
- `posts`: 1 row
- `tools`: 23 rows
- `post_tools`: 0 rows

Impact:
- thin archive
- weak long-tail coverage
- weak internal linking density
- lower trust as a media/editorial platform

### 11. Career pages are not yet true editorial category pages
Severity: High

`/areas` now presents itself as careers discovery, but it still behaves more like a filterable tool list than a full editorial hub.

What is missing for SEO strength:
- stronger intro copy per career
- static hub sections per career
- curated links to posts for each career
- FAQs or explanatory blocks
- indexable subpages or canonical sections per career/topic

Impact:
- weak ability to rank for intent clusters like:
  - AI for programming students
  - AI tools for research
  - AI tools for health students
